A model that answers
decisions, not paragraphs.

A System One model takes your application state plus a set of typed questions — yes/no, pick-one, rate — and returns probabilities, not text. One call in, one judgment out, shaped exactly like your code expects.

01 / DEFINITION

§1What a System One model is

It is a small model trained to do one thing: look at a state — the JSON-shaped facts your application already holds — and answer typed questions about it. Three question types cover almost every software decision:

TYPENOUL

"Is this email a phishing attempt?"

Returns noul — the probability of yes. A number you can threshold, average, or escalate on.

→ 0.87

TYPECHOICE

"Which team should handle this?"

Returns the picked option, its confidence, and the probability of every option.

→ billing @ 0.79

TYPESCORE

"How severe is this incident?"

Returns a level on a scale you define — e.g. [low, medium, high, critical] — with confidence.

→ level 3 / 5

All questions in one call share the state but can't see each other's answers. Ask a phishing verdict, a threat category, and a severity in a single request — each is judged independently against the same evidence.

The contract was introduced by TypeSafe's hosted model Jev (api.typesafe.ai) and is implemented open-source by Kev — small local models (0.8B–27B) whose kev.serve exposes the same POST /v1/systemone API. This site's playground speaks that contract.

02 / COMPARISON

§2System One vs an LLM

An LLM generates plausible text. A System One model emits a typed judgment. Same transformer physics — completely different product.

FIG. 2A — side-by-sidesame input, different species
DIMENSIONSYSTEM ONE (JEV / KEV)GENERAL LLM
OUTPUTTyped answers + probabilities: noul 0.87, choice "billing", score 3/5Free text you must parse, validate, and pray over
CONTRACTExact response schema — your code reads fields, not regexesPrompt engineering + JSON-mode + retries
UNCERTAINTYFirst-class: every answer carries a probability you can thresholdConfidence hidden; wrong answers look as fluent as right ones
LATENCY~0.2–1 s — pointer readout over prefill, no token-by-token decodeSeconds to minutes, scaling with answer length
COSTTens of output tokens, flatHundreds–thousands, variable
FAILURE MODELow confidence → route to a human or a bigger modelA confident, fluent, wrong paragraph
TEMPERATURECalibrated by the training run; not a knob you babysitYou tune it away and hope
Field data, this machine (DGX Spark): on the m-bench system1 suite (49 real decision tasks, 98 generations), Jev scored 98.0 % at 0.27 s/question over WAN, Kev-27B 98.0 % local, Kev-4B 95.9 % at 0.23 s in ~15 GiB. On a 16-email adjudicated phishing corpus behind a production classifier arm, Jev, Kev-4B and Kev-27B all scored F1 1.000. Measured, not model-card numbers.
03 / FIT

§3When to reach for it

USE IT WHEN✓
RoutingWhich queue / team / model handles this request?
DetectionPhishing, fraud, abuse, prompt-injection flags
PolicyRefund eligible? SLA breached? Access allowed?
TriageSeverity score, dedup/match, priority ordering
Gates"Confident enough to auto-approve, or escalate?"

Anywhere your code today says if (model_said_yes) after parsing prose — that is a System One call.

NOT WHEN✕
WritingAnything a human reads — emails, docs, summaries
ReasoningMulti-step logic, math, planning, debugging
GenerationCode, SQL, config, long answers
Open worldQuestions whose answer space you can't enumerate

If the output is a paragraph, you want the LLM. If the output is a decision, you want System One — often both, LLM for talk, S1 for the calls.

04 / THE CONTRACT

§4Anatomy of a query

One POST. Two payloads. state is what your app knows; questions is what you need decided.

FIG. 4A — REQUEST
POST /v1/systemone          # kev.serve :8009 · api.typesafe.ai/v1
Authorization: Bearer <key> # hosted Jev only; kev needs none

{
  "model": "kev-latest",
  "state": {
    "subject": "Your account has been locked",
    "body":    "Verify within 24h at secure-verify.example.com",
    "from":    "it-helpdesk@corp-itdesk.example.com"
  },
  "questions": {
    "is_phishing": {"type": "noul",
      "instructions": "Is this email a phishing attempt?"},
    "threat_type": {"type": "choice",
      "instructions": "What kind of threat is this?",
      "criteria": {"credential_harvesting": null,
        "malware": null, "spam": null, "benign": null}},
    "severity": {"type": "score",
      "instructions": "How dangerous is this email?",
      "criteria": ["harmless","annoying","risky","dangerous"]}
  }
}
FIG. 4B — RESPONSE
{
  "model": "kev-latest",
  "answers": {
    "is_phishing": {"type": "noul", "noul": 0.8705},
    "threat_type": {
      "type": "choice",
      "choice": "credential_harvesting",
      "confidence": 0.7937,
      "probabilities": {
        "credential_harvesting": 0.8453,
        "malware":   0.0018,
        "spam":      0.0135,
        "benign":    0.1394 }},
    "severity": {"type": "score", "score": 2.15,
                 "confidence": 0.61}   // continuous 0..n-1
  },
  "usage": {"input_tokens": 64, "output_tokens": 109},
  "latency_ms": 1116
}

The fields that matter

stateJSON object of facts. Put what a human decider would need — subject, body, sender, order age — not your whole database row. It is the model's entire world for this call.
instructionsThe question, phrased like a spec clause. "Is this email attempting to harvest credentials?" beats "phish?"
criteriaThe answer space. Choice: {option: description|null} — describe an option when its name alone is ambiguous. Score: ordered list of level names. Noul: optional {true, false} descriptions to pin down what each verdict means.
modelkev-latest on a local kev.serve; jev-latest on TypeSafe's hosted API.

Companion endpoints on kev.serve: /v1/systemone/permute re-runs a choice question with shuffled option orders (detects position bias), /v1/systemone/separate runs each question in its own forward pass.

05 / PRACTICE

§5Writing good questions

The model is only as precise as the question. Five rules, then three worked examples you can load straight into the playground.

Rules

1 · one axis"Is it phishing AND urgent?" is two questions. Split them — each question is one decision axis.
2 · name your enumsOption keys should be the strings your code switches on: credential_harvesting, not "stealing passwords".
3 · spec, not vibesInstructions read like a reviewer checklist item, not a chat prompt.
4 · trim the stateIrrelevant fields cost tokens and dilute attention. Include what a human judge would read.
5 · borderline is signalA noul ≈ 0.5 isn't a bug — it's the model saying "escalate me". Threshold honestly.

Worked examples — click to load

EX. AEMAIL TRIAGE

noul "is_phishing" · choice "threat_type" · score "severity"

Three independent judgments over one email. This is the exact shape the production anti-phishing pipeline uses.

EX. BREFUND ROUTING

noul "eligible" · choice "team" · noul "needs_human"

A policy decision + a routing decision + an escalation flag — one call.

EX. CREVIEW MODERATION

choice "sentiment" · noul "fake_review" · score "stars"

Classification and a suspicion flag on a product review.

06 / INTEGRATION

§6Using an endpoint programmatically

ENDPOINTBASE URLAUTHMODEL
Kev (local)http://localhost:8009/v1nonekev-latest
Jev (hosted)https://api.typesafe.ai/v1Authorization: Bearer KEYjev-latest

Run Kev locally: pip install "kev[serve]" (or uv sync --extra serve from a clone), then python -m kev.serve --run jaredpalmer/kev-4b --port 8009. Weights download from the Hub on first run.

CURL
curl -s $BASE/systemone \
  -H 'content-type: application/json' \
  # -H "authorization: Bearer $KEY"  (jev)
  -d '{
    "model": "kev-latest",
    "state": {"text": "…"},
    "questions": {
      "angry": {"type": "noul",
        "instructions": "Is the customer angry?"}
    }
  }'
PYTHON
import httpx

r = httpx.post(
    f"{BASE}/systemone",
    json={
        "model": "kev-latest",
        "state": {"text": "…"},
        "questions": {
            "angry": {
                "type": "noul",
                "instructions":
                    "Is the customer angry?",
            }
        },
    },
    timeout=30,
)
p_yes = r.json()["answers"]["angry"]["noul"]
if p_yes >= 0.7:
    escalate()
JAVASCRIPT
const r = await fetch(`${BASE}/systemone`, {
  method: "POST",
  headers: {"content-type": "application/json"},
  body: JSON.stringify({
    model: "kev-latest",
    state: { text: "…" },
    questions: {
      angry: { type: "noul",
        instructions: "Is the customer angry?" },
    },
  }),
});
const { answers } = await r.json();
escalateIf(answers.angry.noul >= 0.7);
Browser note. kev.serve sends Access-Control-Allow-Origin: *, so a page can call it directly — but Chrome's Private Network Access blocks an HTTPS page → http://localhost or LAN-IP fetch. Also note the server binds 127.0.0.1 by default: to reach it from another device, start it with --host 0.0.0.0. If the playground shows a connection error: serve this page locally (git clone → python3 -m http.server → http://localhost:8000), use Firefox/Safari, or expose the endpoint over HTTPS. Hosted Jev over HTTPS is unaffected.
